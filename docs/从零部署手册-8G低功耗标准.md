# AI-helper 从零部署手册（8G 低功耗标准）

> 适用场景：在一台**全新电脑**上，从零把 AI-helper（微信小程序 + Spring Boot + 本地 Ollama）跑起来。
> **硬件标准：8GB 内存笔记本，低功耗运行。本手册所有参数均按此标准设定，请勿按更大内存的机器上调。**
> 本手册的每一步都在真实机器上验证过（部署实录见第十四节）。

---

## 〇、阅读须知（先看这里）

本文档全程使用下列**路径与端口变量**，请先替换成你自己机器的值，再照着执行：

| 变量 | 本文档取值 | 说明 |
|---|---|---|
| 组件安装根目录 | `D:\tools` | JDK / Maven / MySQL / Redis / Ollama 都装在这里。**没有 D 盘也可以换成 `C:\tools`**，但要全文统一替换 |
| 项目目录 | `D:\1` | `git clone` 的目标路径。**可以换成任意路径**（如 `D:\projects\ai-helper`），同样要全文统一替换 |
| 代理端口 | `127.0.0.1:9674` | 见 2.3 节。**没有代理就跳过所有 `-x $proxy` 与 `$env:HTTPS_PROXY`** |
| MySQL 端口 | `3307` | 见第五节。**若 3306 空闲也可用 3306**，但 MySQL 配置与 `application.yml` 要同步改 |

**执行约定（都是实际踩过的坑）**：

1. **代码块建议在同一个 PowerShell 会话里顺序执行**——部分变量（`$proxy`、`$dl`、`$jdk`）会跨节复用。中途重开会话请重新定义。
2. **含中文的 `.ps1` 脚本必须存成 UTF-8 with BOM**，否则 PowerShell 5.1 会把中文读成乱码。
3. **JDK 目录名带版本号且会随下载时间变化**（本文档写作时是 `jdk-17.0.20.1+1`）。本手册已用**动态方式**定位它，照抄即可；若你自行手写命令，务必注意这一点。
4. 本文档假设 **Windows 10/11 x64 + 系统自带 PowerShell 5.1**。

## 一、硬件标准与设计原则

| 项 | 标准 | 说明 |
|---|---|---|
| 内存 | **8GB** | 所有参数围绕它设定 |
| 磁盘可用空间 | ≥ 30GB | 模型 1.9GB + Ollama 1.4GB + MySQL 约 1GB + Maven 依赖约 500MB |
| CPU | 4 核及以上 | 无独显也**可以**，Ollama 走纯 CPU 推理 |
| 显卡 | 无要求 | 无独显则走纯 CPU 推理；**有独显会自动加速**（见第十五节）。无论哪种，都**不要换 7B 以上模型** |
| 系统 | Windows 10/11 x64 | - |

### 低功耗三原则（贯穿全文）

1. **模型只用 3B 级**——`qwen2.5:3b-16k` 是上限，换 7B/8B 会 OOM 并可能留下 JVM 崩溃日志。
2. **一切并发压到 1**——Ollama 只加载 1 个模型、并发 1；JVM 堆锁 512MB；MySQL 缓冲池锁 128MB。
3. **答辩现场只开必要进程**——IDEA 可不启动（用命令行跑后端），微信开发者工具、浏览器尽量少开。

> ⚠️ 8GB 机型同时开「IDEA + 微信开发者工具 + Ollama + MySQL + 后端」会非常吃紧。开发阶段可以都开，**真实答辩时请改用命令行启动后端并关掉 IDEA**。

> 📌 **本文档默认目标机器没有独立显卡**（Ollama 走纯 CPU 推理）。若你的机器带 NVIDIA 独显（如荣耀猎人 V700 的 RTX 2060 6G），请先看 **第十五节**——GPU 会自动接管推理，速度差异很大，并且有三个额外检查点。

### 2.2 统一目录约定（本文档全程使用）

> 📌 下列路径**可以按需替换**（没有 D 盘就换 C 盘、项目想放别处也完全可以），替换规则见 **第〇节 阅读须知**——关键是**全文保持一致**。

```
D:\tools\                     ← 所有组件安装在这里（不占系统盘）
  downloads\                  ← 安装包
  jdk17\                      ← JDK
  maven\                      ← Maven（含 settings.xml）
  mysql8\                     ← MySQL（含 my.ini 与 data）
  redis\                      ← Redis
  ollama\                     ← Ollama（含 models）
  start-ai-helper.ps1         ← 一键启动脚本
D:\1\                         ← 项目代码（git clone 到这里）
D:\ai wordplace\              ← 附件（视频/报告）自动创建
```

### 2.3 关于网络代理

若所在网络访问 GitHub/模型仓库困难，需要本地代理。本手册以 `127.0.0.1:9674` 为例，**请替换为你自己的端口**。命令行工具不会自动读取系统代理，必须显式指定：

```powershell
$proxy = "http://127.0.0.1:9674"    # ← 改成你的实际端口
```

### 2.4 安装 Git 并获取项目代码

```powershell
# 若已装 Git（git --version 有输出），直接跳到第 3 步
$dl = "D:\tools\downloads"
New-Item -ItemType Directory -Force -Path $dl | Out-Null
cd $dl
curl.exe -L --retry 3 -x $proxy -o PortableGit.7z.exe "https://github.com/git-for-windows/git/releases/download/v2.55.0.windows.5/PortableGit-2.55.0.5-64-bit.7z.exe"

# 1) 自解压（无需管理员权限）
& "$dl\PortableGit.7z.exe" -o"D:\tools\PortableGit" -y

# 2) 加入用户 PATH
$gitPath = "D:\tools\PortableGit\cmd"
$p = [Environment]::GetEnvironmentVariable("Path","User")
if ($p -notlike "*$gitPath*") { [Environment]::SetEnvironmentVariable("Path", $p.TrimEnd(';') + ";" + $gitPath, "User") }
$env:Path += ";" + $gitPath
git --version

# 3) 克隆项目代码到项目目录（本项目是公开仓库，HTTPS 匿名即可 clone）
git clone https://github.com/kunkun-text/ai_helper.git D:\1
```

> - PortableGit 链接若失效，去 <https://github.com/git-for-windows/git/releases> 找最新的 `PortableGit-*-64-bit.7z.exe`。
> - **只有需要推送代码时才要配凭据**（SSH key 或 HTTPS + Personal Access Token）；纯部署不用管。
> - `git clone` 需要网络通畅，若走代理请确保代理支持 HTTPS 且已设置 `$env:HTTPS_PROXY`。

## 三、安装 JDK 17

> 项目 `pom.xml` 要求 Java 17。若机器已有 JDK 8/11，**不要复用**，另装 17。

```powershell
$dl = "D:\tools\downloads"
New-Item -ItemType Directory -Force -Path $dl, "D:\tools\jdk17" | Out-Null
cd $dl
curl.exe -L --retry 3 -x $proxy -o temurin-jdk17.zip "https://api.adoptium.net/v3/binary/latest/17/ga/windows/x64/jdk/hotspot/normal/eclipse"
tar -xf temurin-jdk17.zip -C "D:\tools\jdk17"
# 动态定位 JDK 目录（目录名带版本号且会变，不要写死）
$jdk = (Get-ChildItem "D:\tools\jdk17" -Directory | Select-Object -First 1).FullName
Write-Host "JDK 目录: $jdk"

# 配置环境变量（用户级，无需管理员）
[Environment]::SetEnvironmentVariable("JAVA_HOME", $jdk, "User")
$p = [Environment]::GetEnvironmentVariable("Path","User")
[Environment]::SetEnvironmentVariable("Path", $p.TrimEnd(';') + ";" + $jdk + "\bin", "User")

& "$jdk\bin\java.exe" -version       # 应输出 17.x
```

## 四、安装 Maven

```powershell
cd "D:\tools\downloads"
curl.exe -L --retry 3 -x $proxy -o maven.zip "https://archive.apache.org/dist/maven/maven-3/3.9.9/binaries/apache-maven-3.9.9-bin.zip"
New-Item -ItemType Directory -Force -Path "D:\tools\maven" | Out-Null
tar -xf maven.zip -C "D:\tools\maven"

$mvnHome = "D:\tools\maven\apache-maven-3.9.9"
$p = [Environment]::GetEnvironmentVariable("Path","User")
[Environment]::SetEnvironmentVariable("Path", $p.TrimEnd(';') + ";" + $mvnHome + "\bin", "User")

# 写入 settings.xml：走代理 + 本地仓库放 D 盘（省 C 盘）
$settings = '<settings xmlns="http://maven.apache.org/SETTINGS/1.2.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="http://maven.apache.org/SETTINGS/1.2.0 https://maven.apache.org/xsd/settings-1.2.0.xsd"><localRepository>D:/tools/maven-repo</localRepository><proxies><proxy><id>local-http-proxy</id><active>true</active><protocol>http</protocol><host>127.0.0.1</host><port>9674</port><nonProxyHosts>localhost|127.0.0.1</nonProxyHosts></proxy></proxies></settings>'
Set-Content -Path "$mvnHome\conf\settings.xml" -Value $settings -Encoding ASCII

$env:JAVA_HOME = $jdk
& "$mvnHome\bin\mvn.cmd" -v        # 应显示 Java version: 17.x
```

> **注意**：`settings.xml` 里的 `<host>/<port>` 要换成你自己的代理地址。若直连无碍，可删掉整个 `<proxies>` 段。

## 五、安装 MySQL 8

> **为什么不能用 MySQL 5.5/5.7**：`docs/schema.sql` 中使用了 `COLLATE utf8mb4_0900_ai_ci`，这是 **MySQL 8.0 专属**排序规则，低版本会直接执行失败。

### 5.1 解压与配置

```powershell
cd "D:\tools\downloads"
curl.exe -L --retry 3 -x $proxy -o mysql8.zip "https://dev.mysql.com/get/Downloads/MySQL-8.0/mysql-8.0.40-winx64.zip"
New-Item -ItemType Directory -Force -Path "D:\tools\mysql8" | Out-Null
tar -xf mysql8.zip -C "D:\tools\mysql8"
New-Item -ItemType Directory -Force -Path "D:\tools\mysql8\data" | Out-Null
```

创建 `D:\tools\mysql8\my.ini`（**已按 8G 低功耗调优**）：

```ini
[mysqld]
basedir=D:/tools/mysql8/mysql-8.0.40-winx64
datadir=D:/tools/mysql8/data
port=3307
bind-address=127.0.0.1
character-set-server=utf8mb4
collation-server=utf8mb4_0900_ai_ci
max_connections=50
innodb_buffer_pool_size=128M
log-error=D:/tools/mysql8/mysql-error.log

[client]
port=3307
default-character-set=utf8mb4
```

> **端口为何是 3307**：如果机器上已有 MySQL 占用 3306，不要动它，用 3307 并存。若新机器 3306 空闲，也可以改成 3306，但要同步改 `application.yml`。

### 5.2 初始化并启动

```powershell
$bin = "D:\tools\mysql8\mysql-8.0.40-winx64\bin"

# 初始化（root 初始为空密码）
& "$bin\mysqld.exe" --defaults-file="D:\tools\mysql8\my.ini" --initialize-insecure --console

# 启动
Start-Process -FilePath "$bin\mysqld.exe" -ArgumentList "--defaults-file=D:\tools\mysql8\my.ini" -WindowStyle Hidden
Start-Sleep -Seconds 15
Get-NetTCPConnection -LocalPort 3307 -State Listen      # 有输出即成功
```

### 5.3 建库导表

```powershell
$my = "D:\tools\mysql8\mysql-8.0.40-winx64\bin\mysql.exe"

# ⚠️ 参数必须分开写（-h 127.0.0.1），写成 -h127.0.0.1 在 PowerShell 下会被解析成 host "127"
& $my -u root -h 127.0.0.1 -P 3307 -e "ALTER USER 'root'@'localhost' IDENTIFIED BY '123456'; FLUSH PRIVILEGES;"

# 导入表结构（脚本自带 CREATE DATABASE 与 USE）
& $my -u root -p123456 -h 127.0.0.1 -P 3307 --default-character-set=utf8mb4 -e "source D:/1/docs/schema.sql"

# 确认 9 张表都在
& $my -u root -p123456 -h 127.0.0.1 -P 3307 -e "SHOW TABLES FROM ai_helper;"
```

预期表清单：`defense_answers`、`defense_questions`、`defense_records`、`defense_score_record`、`defense_student_questions`、`defense_topics`、`system_settings`、`users`、`voice_responses`

## 七、安装 Ollama 与模型

### 7.1 解压

```powershell
cd "D:\tools\downloads"
curl.exe -L --retry 3 -x $proxy -o ollama.zip "https://github.com/ollama/ollama/releases/latest/download/ollama-windows-amd64.zip"
New-Item -ItemType Directory -Force -Path "D:\tools\ollama\models" | Out-Null
tar -xf ollama.zip -C "D:\tools\ollama"
```

### 7.2 先固化低功耗环境变量（**关键步骤**）

8G 机器**必须**用下面这组参数，否则加载模型会因内存不足失败。

```powershell
foreach ($kv in @(
    @("OLLAMA_MODELS",            "D:\tools\ollama\models"),
    @("OLLAMA_NUM_PARALLEL",      "1"),
    @("OLLAMA_MAX_LOADED_MODELS", "1"),
    @("OLLAMA_KV_CACHE_TYPE",     "q4_0"),
    @("OLLAMA_NUM_THREADS",       "4")
)) { [Environment]::SetEnvironmentVariable($kv[0], $kv[1], "User") }
```

| 变量 | 值 | 作用 |
|---|---|---|
| `OLLAMA_MODELS` | `D:\tools\ollama\models` | 模型存 D 盘，不占 C 盘 |
| `OLLAMA_NUM_PARALLEL` | `1` | 并发压到 1，避免多份 KV 缓存 |
| `OLLAMA_MAX_LOADED_MODELS` | `1` | 同时只保留 1 个模型 |
| `OLLAMA_KV_CACHE_TYPE` | `q4_0` | KV 缓存量化，**内存需求直接减半** |
| `OLLAMA_NUM_THREADS` | `4` | 低功耗；按 CPU 物理核心数设，8G 机型建议 4 |

### 7.3 启动服务并拉取模型

```powershell
# 让本次会话的变量生效
$env:OLLAMA_MODELS          = "D:\tools\ollama\models"
$env:OLLAMA_NUM_PARALLEL    = "1"
$env:OLLAMA_MAX_LOADED_MODELS = "1"
$env:OLLAMA_KV_CACHE_TYPE   = "q4_0"
$env:OLLAMA_NUM_THREADS     = "4"
$env:HTTPS_PROXY = $proxy        # 拉模型需要走代理
$env:HTTP_PROXY  = $proxy

Start-Process -FilePath "D:\tools\ollama\ollama.exe" -ArgumentList "serve" -WindowStyle Hidden
Start-Sleep -Seconds 8

& "D:\tools\ollama\ollama.exe" pull qwen2.5:3b                                   # 1.9GB
& "D:\tools\ollama\ollama.exe" create qwen2.5:3b-16k -f "D:\1\Modelfile-qwen25"  # 派生 16k 上下文版本
& "D:\tools\ollama\ollama.exe" list
```

`Modelfile-qwen25` 是仓库自带的，只有两行：

```
FROM qwen2.5:3b
PARAMETER num_ctx 16384
```

### 7.4 冒烟测试

```powershell
$body = '{"model":"qwen2.5:3b-16k","messages":[{"role":"user","content":"hi"}],"stream":false,"options":{"num_predict":10}}'
[System.IO.File]::WriteAllText("$env:TEMP\o.json", $body, (New-Object System.Text.UTF8Encoding $false))
curl.exe -s -X POST http://127.0.0.1:11434/v1/chat/completions -H "Content-Type: application/json" --data-binary "@$env:TEMP/o.json" --max-time 300
```

能返回 `"content":"..."` 即成功。**首次调用会慢**（要加载模型，纯 CPU 机器约 10–60 秒），之后单轮推理（100 tokens 量级）约 10–15 秒。带独显的机器会明显更快（见第十五节）。

## 八、配置 application.yml

`src/main/resources/application.yml` **被 `.gitignore` 排除**，每台新机器都要自己放一份：

```powershell
cd D:\1\src\main\resources
Copy-Item application.yml.example application.yml
```

然后按下面三处修改（其余保持模板默认）：

```yaml
spring:
  datasource:
    # ① 端口改成 MySQL 实际端口
    url: jdbc:mysql://127.0.0.1:3307/ai_helper?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    username: root
    password: 123456                    # ② 改成你的 MySQL 密码

  data:
    redis:
      host: 127.0.0.1
      port: 6379
      password: 123456                  # ③ 与 redis-local.conf 的 requirepass 一致

  mail:
    # ⚠️ 未配置时「忘记密码」功能不可用，注册/登录/答辩不受影响
    username: your-qq-mail@qq.com       # 换成自己的 QQ 邮箱
    password: your-qq-auth-code         # SMTP 授权码（不是 QQ 登录密码）
```

模型名**不要动**（`qwen2.5:3b-16k`），硬件红线在模板注释里已写明。

## 九、编译并启动后端

```powershell
# JDK 目录动态定位（重开过会话就在这里重新取一次，不要写死版本号）
$jdk = (Get-ChildItem "D:\tools\jdk17" -Directory | Select-Object -First 1).FullName
$env:JAVA_HOME = $jdk
$env:Path = "$jdk\bin;D:\tools\maven\apache-maven-3.9.9\bin;" + $env:Path
cd D:\1

# 首次编译要下载依赖（走代理），约 2–3 分钟
mvn -B -DskipTests compile

# 启动（-Xmx512m 是 8G 机型的硬性要求，不要调大）
mvn -B spring-boot:run -Dspring-boot.run.jvmArguments=-Xmx512m
```

看到下面这行就是成功：

```
Started AiHelperApplication in X.XXX seconds
```

**内存紧张时的替代启动方式**（不开 IDEA，省 1–2GB）：

```powershell
Start-Process -FilePath "D:\tools\maven\apache-maven-3.9.9\bin\mvn.cmd" `
  -ArgumentList @("-B","spring-boot:run","-Dspring-boot.run.jvmArguments=-Xmx512m") `
  -WorkingDirectory "D:\1" `
  -RedirectStandardOutput "D:\1\logs\backend-stdout.log" `
  -RedirectStandardError  "D:\1\logs\backend-stderr.log" -WindowStyle Hidden
```

日志在 `D:\1\logs\backend-stdout.log`。附件会自动落到 `D:\ai wordplace`（模板中 F 盘不存在时会自动降级到 D 盘）。

## 十、小程序前端

**不需要改任何配置**。`src/main/resources/static/Ai/utils/config.js` 中：

```js
localServerUrl: 'http://localhost:8080',
useRemoteServer: false          // false = 用 localServerUrl，开发者工具调试最稳
```

用微信开发者工具打开目录：

```
D:\1\src\main\resources\static\Ai
```

若提示域名不合法：**详情 → 本地设置 → 勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」**。

`project.config.json` 的 `appid` 为 `touristappid`（游客模式）时可直接运行；若需要真机调试，改回自己的 AppID，并把 `config.js` 的 `useRemoteServer` 改为 `true`、`serverUrl` 改为本机 WLAN 的 IPv4 地址。

## 十三、常见问题（8G 机型高发）

### Q1. 模型加载失败：`failed to allocate CPU_REPACK buffer` 或 `unable to allocate CPU buffer`

**这是 8G 机型最常见的问题**，根因是 Windows「提交内存」不足（提交上限 = 物理内存 + 分页文件）。按顺序排查：

1. **确认低功耗变量已生效**（`OLLAMA_KV_CACHE_TYPE=q4_0` 能把需求从 1.24GB 降到约 600MB）。
2. **调大分页文件**——这是根治手段。检查当前值：
   ```powershell
   Get-CimInstance Win32_OperatingSystem | Select-Object @{N='提交上限GB';E={[math]::Round($_.TotalVirtualMemorySize/1MB,2)}}, @{N='提交可用GB';E={[math]::Round($_.FreeVirtualMemory/1MB,2)}}
   Get-CimInstance Win32_PageFileUsage | Select-Object Name, AllocatedBaseSize
   ```
   若分页文件小于 4GB，**请调到 8–16GB**（建议放 D 盘），改完重启生效：
   ```powershell
   # 先确认 D 盘没有已登记的分页文件，再执行
   $exist = Get-CimInstance Win32_PageFileSetting | Where-Object { $_.Name -like "D:*" }
   if (-not $exist) {
       $pfClass = [WmiClass]"root\cimv2:Win32_PageFileSetting"
       $pf = $pfClass.CreateInstance()
       $pf.Name = "D:\pagefile.sys"; $pf.InitialSize = 8192; $pf.MaximumSize = 16384
       $pf.Put()
   }
   Get-CimInstance Win32_PageFileSetting | Select-Object Name, InitialSize, MaximumSize
   ```
3. **关掉不必要的程序**（浏览器、QQ、IDEA）后重启 Ollama 再试。

### Q2. 后端启动报错或极其缓慢

- 先确认 MySQL 与 Redis 都在跑（后端启动时会连它们）。
- 确认 `-Xmx512m` 已加上，否则默认堆可能吃掉 1/4 物理内存。

### Q3. Maven 下载依赖卡住

- 检查 `settings.xml` 的代理配置是否与当前代理端口一致（代理端口常会变）。
- 或临时用阿里云镜像。

### Q4. 小程序请求全部失败

- 确认后端 8080 在跑。
- 确认开发者工具已勾选「不校验合法域名」。
- 真机调试时 `config.js` 的 `serverUrl` 要填本机 WLAN 的 IPv4 地址，**不要用虚拟网卡地址**（Hyper-V/VMware 的 172.31.x / 192.168.x 网段）。

### Q5. 答辩途中机器卡死

- 8G 机型请**答辩现场只开必要进程**：MySQL + Redis + Ollama + 后端 + 微信开发者工具。
- 用 `-Xmx512m` 跑后端，不要用 IDEA 启动。

## 十四、部署实录（本次验证机器）

本次部署在一台 **16GB 内存**的开发机上完成，作为 8G 标准的参照。差异点如下，实际部署 8G 机型时**请以本手册正文为准**：

| 项 | 本次实录（16G 机器） | 8G 标准（本手册正文） |
|---|---|---|
| `OLLAMA_NUM_THREADS` | 8 | **4** |
| `innodb_buffer_pool_size` | 256M | **128M** |
| `max_connections` | 100 | **50** |
| JVM 堆 | -Xmx512m | -Xmx512m（不变） |
| 实时推理速度 | 9.89 tokens/s（纯 CPU 稳定值） | 预计更慢，单轮 40 秒以上 |

**关于推理速度的关键提示**：本次验证的机器**没有独立显卡**，Ollama 是纯 CPU 推理（日志中 `library=cpu`、`total_vram="0 B"`），9.89 tokens/s 已是该 CPU 的正常水平。**若发现响应异常慢，先检查是否存在多个残留的 `llama-server` 进程**——本次实测曾出现 3 个实例同时占用 6.3GB 内存、可用物理内存跌到 1.1GB，速度明显下降。清理方法：

```powershell
Get-Process ollama, llama-server -ErrorAction SilentlyContinue | Stop-Process -Force
Start-Sleep -Seconds 5
# 再用第十二节的 start-ai-helper.ps1 重新拉起服务
```

**本次部署实测结果**：MySQL 8 表结构导入 9 张表正常；Redis 连通；Ollama 0.34.4 成功构建 `qwen2.5:3b-16k` 并完成推理；后端 4.28 秒启动成功；注册/登录/建课题/首轮出题全部跑通。

### ⚠️ 已知问题（新机器部署同样会遇到）

部署验证时发现：**AI 评分不落库**，原因是 `ChatConfiguration.java` 的 `.defaultTools(textTools)` 让 3B 模型把工具调用输出成了普通文本（形如 `{"name": "getVideoContentByTopicId"...}`），导致回复里没有「评分:」行，`defense_score_record` 表为空、答辩轮次无法推进。

该问题与硬件无关，属于代码在新版 Ollama（0.34.4 实测）下的适配问题。在未修复前，新机器部署会复现同样现象（表现为「有题无分、答辩无法收尾」），部署完成后请按第十一节清单逐项验证，若第 5、6 项正常但答辩无分数，即为该问题。

## 十五、下一台目标机器硬件画像（荣耀猎人 V700）

> 本节记录硬件对比信息，以及这些差异对部署的**实际影响**。
> **本手册的部署标准保持不变**（8GB 内存 · 低功耗 · `qwen2.5:3b-16k`），本节只说明在新机器上部署时需要留意什么。

### 15.1 与上一台（光影精灵 7）的硬件对比

**荣耀猎人 V700 更强的地方**

| 项 | 荣耀猎人 V700 | 光影精灵 7（上一台） | 对部署的意义 |
|---|---|---|---|
| **显卡显存** | **RTX 2060 · 6GB** | RTX 3050 · 4GB | **最关键**：6G 跑 7B 量化模型不容易爆显存，4G 很容易跑崩 |
| 电池 | 健康度 78%，循环 142 次 | 同年代机型普遍衰减更严重 | 状态更好，但答辩现场仍建议插电 |
| 散热 | 风谷散热设计 | — | 满载温度控制更稳，长时间推理不易降频 |

**荣耀猎人 V700 更弱的地方**

| 项 | 荣耀猎人 V700 | 光影精灵 7 | 对部署的意义 |
|---|---|---|---|
| CPU | i5-10300H（4 核 8 线程） | i5-11400H（6 核 12 线程） | 多开 IDEA、Maven 打包、同时跑多个后端项目时更慢 |
| 内存频率 | 2667 MHz | 3200 MHz | 内存读写更慢 |

### 15.2 这些差异对部署的实际影响

**① 有独显 → Ollama 会自动走 GPU，这是最大的变化**

不需要改任何配置。Ollama 启动时自动检测 NVIDIA 显卡，检测到就切 CUDA 引擎。判断方法看 Ollama 日志这一行：

- 走 GPU：`inference compute id=... library=cuda ... total_vram="6.0 GiB"`
- 走 CPU：`inference compute id=cpu library=cpu total_vram="0 B"`

速度预期（3B 模型估算）：GPU 比纯 CPU 通常快 5–10 倍，单轮答辩有望回到 **3–6 秒**（纯 CPU 是 15–19 秒）。

**② 第七节的低功耗环境变量仍要保留，但作用会变化**

| 变量 | 在带独显机器上的实际作用 |
|---|---|
| `OLLAMA_MODELS` | 仍然重要——决定模型存在哪个盘 |
| `OLLAMA_NUM_PARALLEL=1`、`OLLAMA_MAX_LOADED_MODELS=1` | 仍然重要——控制并发，避免多份 KV 缓存挤爆显存 |
| `OLLAMA_KV_CACHE_TYPE=q4_0` | **建议保留**——16k 上下文在 6G 显存下更稳妥 |
| `OLLAMA_NUM_THREADS=4` | 影响很小——GPU 承担主要计算，CPU 只做调度 |

**③ 模型标准不变，但 6G 显存确实留了余量**

- 本手册当前标准仍是 `qwen2.5:3b-16k`，**暂不上调**（低功耗优先）
- 6G 显存理论上够跑 7B 量化模型（Q4_K_M 权重约 4.4GB），但**16k 上下文需配合 KV 量化**才放得下，否则仍会溢出到系统内存
- 换更大模型属于后续评估项，需同步确认 `CLAUDE.md` 里的硬件红线说明

**④ CPU 弱一截的实际影响**

- Maven 首次编译会更慢：本机 6 核 12 线程耗时 2 分 19 秒，4 核 8 线程预计 **4 分钟左右**
- 首次拉依赖时不要同时开 IDEA 编译
- 推理本身不受影响（由 GPU 承担）

**⑤ 内存频率低（2667 vs 3200）的影响**

- **只影响纯 CPU 推理**——CPU 推理的瓶颈正是内存带宽
- 有独显时模型常驻显存，系统内存频率影响很小
- 唯一要留意的是 16k 上下文的 KV 缓存若被换出到分页文件会明显拖慢，所以第十三节 Q1 的分页文件调整仍然要做

**⑥ 电池与散热**

- 电池健康 78%：答辩/演示**务必插电源**，不要赌续航
- 散热底子好：连续 10 轮答辩不会明显降频

### 15.3 在新机器上部署时的三个额外检查点

1. **装好 NVIDIA 驱动**：用 `nvidia-smi` 验证驱动正常，Ollama 才能识别 CUDA。
2. **确认 GPU 真的生效**：启动后看日志出现 `library=cuda` 即为成功；若仍是 `library=cpu`，说明驱动或 CUDA 运行库没到位。
3. **显存不足的报错形态不同**：GPU 机器显存不够会报 `CUDA out of memory`（而不是第十三节 Q1 的 CPU buffer 分配失败），此时降低 `OLLAMA_NUM_PARALLEL` 或保留 `q4_0` KV 缓存即可。

**除以上三点外，本手册其余步骤完全一致，无需改动。**
