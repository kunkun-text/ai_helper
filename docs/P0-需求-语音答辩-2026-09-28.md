## 一、需求目标

| # | 目标 | 说明 |
|---|---|---|
| 1 | **AI 发音提问** | 每轮题目由 AI 语音播报（文本来自现有题库 / 模型自拟追问） |
| 2 | **学生语音回答** | 学生按住录音说话，松开后自动转成文字 |
| 3 | **一来一回** | 与文字答辩一致的 5 预设题 + 5 追问 = 10 轮节奏 |
| 4 | **规格对齐文字答辩** | 同一套评分口径、同一批表、同一套收尾与续答逻辑 |
| 5 | **并列的功能模块** | 与「视频上传」「报告上传」「文字答辩」同级，作为答辩系统的第 4 个功能块 |

**核心设计原则（决定实现难度）**：

> **语音只是「输入 / 输出的载体」，不是新流程。**
> AI 提问 → 前端把题目文本**念出来**；学生回答 → 前端把语音**转成文字** → 拿这段文字去调**现有的 `/api/chat`**。
> 于是：评分、五维、落库、轮次计数、收尾、续答、三档复核、防作弊 —— **全部零改动复用**。

## 四、全流程设计

```
① 学生进入语音答辩页
   └─ 复用 /api/chat/resume-info（探测未完成场次）→ 弹窗「继续作答 / 重新开始」   ← 现有逻辑，直接调
   └─ 复用 /api/chat/clear（新建或续答）                                        ← 现有逻辑，直接调

② AI 提问（Loop 每一轮）
   └─ 后端返回三段式文本（点评 / 评分 / 下一题）                                 ← 现有逻辑
   └─ 前端从回复中取「下一题:」的题目文本 → 调 TTS → 播放语音                    ← 🆕 前端新增

③ 学生作答
   └─ 按住「录音」→ 说话 → 松开                                                ← 🆕 前端新增
   └─ ASR 语音转文字 → 显示在气泡里（可编辑 / 重录）                            ← 🆕 前端新增
   └─ 把这段文字作为 prompt 调 POST /api/chat                                   ← 完全复用现有接口 ✅

④ 评分与落库
   └─ 五维评分、三档标记、复核、幂等、轮次、收尾、总结带总分                     ← 全部复用，零改动 ✅

⑤ 归档（可选 / V2）
   └─ 录音文件上传 → 落本地磁盘 + 写 voice_responses                            ← 🆕 新增（复用文件服务）
```

**关键点：后端答辩主链路几乎不用改** —— 因为 `/api/chat` 收到的仍然是"一段文字"。

## 五、技术方案选型

### 5.1 ASR（学生语音 → 文字）

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. 微信同声传译插件（WechatSI）** | 免费；小程序内直接调；无需后端；自动分段 | 需**真实 AppID** + 小程序后台添加插件；单次有时长上限（约 60s）；专业术语识别一般 | ✅ **建议 V1 采用** |
| B. 后端本地 Whisper（whisper.cpp + small 模型） | 离线、术语可定制、无第三方依赖 | 8G 机器再加 ~0.5GB 内存压力；需额外部署与调试；首次识别慢 | 备选（识别率不足时） |
| C. 在线 ASR（讯飞 / 百度） | 准确率高、术语支持好 | 需密钥、要联网、可能产生费用 | 备选 |

### 5.2 TTS（AI 提问 → 语音）

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. 微信同声传译插件（`textToSpeech`）** | 免费、小程序内直接调、与 ASR 同一插件 | 需真实 AppID；单次文本长度有限（题目 30 字内，足够） | ✅ **建议 V1 采用** |
| B. 后端本地 TTS（Windows SAPI / Edge-TTS）生成 mp3 → 复用文件服务返回 URL | 可控、可缓存（同一题不重复合成） | 8G 机器多一个进程；音色一般；要自己封装 | 备选 |
| C. 在线 TTS | 音质好 | 需密钥、联网、费用 | 备选 |

### 5.3 建议结论

**V1 统一用「微信同声传译插件」**（ASR + TTS 一个插件全包，零后端改动）；
若实测**专业术语识别率不足**（Hadoop / MapReduce / AQI / HDFS 这些词），再切后端本地 Whisper 或在线 ASR。

> ⚠️ 插件的**前置条件**见第十一节 —— 需要真实小程序 AppID，当前项目是游客模式（`touristappid`），这是开工前必须先确认的第一件事。

## 七、数据模型

现成表（`docs/schema.sql`，可直接用）：

```sql
CREATE TABLE voice_responses (
  response_id       INT AUTO_INCREMENT PRIMARY KEY,
  defense_id        INT NULL,          -- 关联 defense_records.defense_id
  question_id       INT NULL,          -- 预设题时填 defense_questions.question_id；追问为 NULL
  question          TEXT NOT NULL,     -- AI 本轮问的题（语音播报的那段文本）
  response_text     TEXT,              -- 学生语音转出的文字（送进 /api/chat 的就是它）
  response_audio_url VARCHAR(255),     -- 录音文件相对 URL（走现有 /files/** 映射）
  response_time     DATETIME
);
```

**建议（可选）**：加 `recognition_confidence` / `edited` 两列，用于区分「识别原文」与「学生手动修改后的答案」；
若不想动表结构，可把两者都塞进 `response_text`（不推荐）。

**落库口径**：`defense_answers.student_answer` 仍存**实际送去评分的文字**（编辑后），保证与评分可比对；
`voice_responses.response_text` 存**ASR 原始输出**，便于排查识别质量。

## 九、验收标准

参照文字答辩规格（`需求清单-2026-09-15.md` 的口径）：

| # | 验收项 | 标准 |
|---|---|---|
| 1 | 提问语音播报 | 每轮题目自动播报，可重播；播报不阻塞录音 |
| 2 | 语音作答 | 按住录音 / 松开结束；有录音中状态与波形/计时提示 |
| 3 | 识别回填 | 识别结果可**编辑**后再发送；识别失败有明确提示 + 一键重录 |
| 4 | 10 轮流程 | 与文字答辩**完全一致**：同题库（q45/q69/q70/q71/q72 + 追问）、同评分口径 |
| 5 | 落库一致 | `defense_score_record` / `defense_answers` / `defense_records` 与文字答辩同结构写入；五维和 == 答案分 |
| 6 | 收尾与续答 | 第 10 轮收尾、总结带总分；中途退出重进（<30 分钟）弹窗可续答 |
| 7 | 音频归档（V2） | `voice_responses` 有逐轮记录，`response_audio_url` 可回放 |
| 8 | 回归 | 文字答辩功能不受影响（同一次提交内不得回归） |

## 十一、前置条件与风险

| # | 事项 | 影响 | 处理 |
|---|---|---|---|
| 1 | **小程序需真实 AppID**（当前 `touristappid` 游客模式），并在小程序后台添加「微信同声传译」插件 | **阻断性** —— 决定 TTS/ASR 能否用插件方案 | **开工第一件事：确认能否申请到 AppID + 加插件**；若不能 → 转后端本地 TTS/Whisper 方案 |
| 2 | 录音权限 `scope.record` 授权 | 首次使用需授权，拒绝后要有引导 | 前端封装权限流程 |
| 3 | 录音/播放 API **仅真机可用** | 开发者工具调试受限，验证成本高 | 提前准备真机走查清单 |
| 4 | 插件需**联网** | 答辩现场断网则语音不可用 | 现场需保证网络；或做好「降级为文字输入」兜底 |
| 5 | 8G 机器 + 录音文件存储 | 磁盘占用增加 | 单轮录音 mp3（约 50KB/s），10 轮约 5~10MB；走现有 `preferred-drives` 自动选盘 |
| 6 | 专业术语识别率（Hadoop / MapReduce / AQI / HDFS） | 识别错字会直接影响评分公平性 | ① 允许学生**编辑后**再提交；② V3 加热词纠错 |
| 7 | 与现有答辩的隔离 | 改坏 `defense.js` 会造成回归 | **独立页面**，不动现有答辩页 |
