## 0. 一句话现状

视频**能上传、能转写、能出五维成绩单**，但：

1. **ASR 输入质量刚改造完**（VAD、音频预处理、有效语音闸门、置信度、纠错词表、视频专用 turbo-q5），
   代码/编译/单测通过，**还没有用真实答辩录像做端到端复测**。
2. **评分仍由本地 `qwen2.5:3b-16k` 完成**。GLM-4.7 / DeepSeek
   **只配好了参数并验证了 key**，调用代码还没写。

所以现在点“AI 评分（基于视频）”，走的是：

```
视频 → ffmpeg 抽音轨(+预处理) → whisper(VAD+JSON) → 纠错词表
     → 本地 3B 写点评 → 本地 3B 打分 → DocScoreParser 服务端守护
     → defense_records.video_analysis（文本成绩单）
```

**不是 GLM，也不是 DeepSeek。**

## 1. 现在能跑通的链路（代码事实）

| 步骤 | 现状 | 关键代码 |
|---|---|---|

| 语音转写 | whisper.cpp；VAD 剔除静音/噪声；视频用 `large-v3-turbo-q5_0`，60 秒语音用 `small`；`-ojf` 输出置信度 | `WhisperAsrServiceImpl.runWhisper`（约 :550）、`resolveModelForTier`（约 :829） |

| 打分 | **本地 3B**：只依据点评打分，不喂原文 | `VideoAnalysisServiceImpl.callScores`（约 :294） |
| 服务端守护 | 缺失压分 → 口语下限 → 跑题归零；总分服务端重算 | `DocScoreParser` |

## 3. 缺口清单（按优先级）

### P0-1 · 云端评分调用（最高优先级，下一步就做这个）

**现状**：只有配置和 key 验证，`VideoAnalysisServiceImpl.callComments` / `callScores`
仍直接调用本地 `chatClient`。GLM/DeepSeek 没有接入。

**要做**：

1. 新增 `Service/AiScoringService`（或 `AiScoringClient`）+ 实现：
   - 用 JDK `HttpClient` + Jackson，**不新增依赖**；
   - 读取 `AppProperties.Ai.Scoring`；
   - 支持 OpenAI 兼容接口：GLM、DeepSeek 共用一套请求/解析；
   - 默认 `temperature=0`、`stream=false`；
   - GLM 请求体加 `"thinking": {"type": "disabled"}`；DeepSeek 不加该字段；
   - 超时：connect 10s / read 120s（配置可调）；
   - 只记录 provider/model/耗时/usage，**绝不打印 api-key**。
2. 回退顺序（每次调用独立回退，失败只降级不抛给前端）：
   `glm-4.7` → `glm-4.5-air` → `deepseek-v4-flash` → 本地 `qwen2.5:3b-16k`。
   - 触发回退的条件：HTTP 非 2xx、连接/读取超时、返回 `content` 为空、JSON 解析失败。
   - 如果云端点评成功、云端打分失败，可以只把打分回退本地；日志要写明每一步用的是哪个引擎。
3. 接进 `VideoAnalysisServiceImpl`：
   - `callComments(...)`：先调 `AiScoringService`；返回空则走原来的本地 `chatClient`；
   - `callScores(...)`：同上，结果仍交给 `DocScoreParser.parse`；
   - 保留现有服务端守护（缺失压分 / 口语下限 / 跑题归零 / 总分重算）。
4. 结果可追溯：
   - 日志至少打印 `评分引擎=glm-4.7`；
   - 建议在 `video_analysis` 成绩单里加一行「评分引擎：glm-4.7」或在 Redis 状态里带 `engine`；
   - 不要改 `analysis_source` 的既有语义（它现在只表示 video/report 来源）。
5. 配置读取：
   - `app.ai.scoring.enabled=false` 或所有 key 为空 → 直接走本地 3B；
   - `fallback-to-local=false` 时，云端失败应明确报错，而不是静默本地。

**验收标准**：

- 用一段已转写文本调用 GLM-4.7 成功，返回五维点评/评分；
- 把 `glm.api-key` 临时改错，能自动回退到 `glm-4.5-air` / DeepSeek / 本地，任务不失败；
- 日志能看到每一步的引擎与耗时；
- `git grep` 仍找不到真实 key；
- 单测至少覆盖：请求体构造（thinking 字段）、响应解析、空 content 回退、超时/非 2xx 回退（可用本地 stub）。

**涉及文件**：

- 新增 `Service/AiScoringService.java`、`Service/Impl/AiScoringServiceImpl.java`
- 改 `Service/Impl/VideoAnalysisServiceImpl.java`（callComments/callScores）
- 可能新增 `pojo/dto/AiScoringResult.java`（content/provider/model/elapsedMs/usage）
- `AppProperties.java` 已有 `Ai.Scoring`，不用再建
- 测试：新增 `AiScoringServiceTest`（纯函数/本地 stub，不连真实 API）

**坑**：

- GLM-4.7 是推理模型，**不关 thinking 会返回空 content**；
- 不要用 `reasoning_content` 当点评；
- GLM 的 `Authorization: Bearer <key>`，key 形如 `id.secret`；
- PowerShell 里用 `curl.exe` 且 JSON 要写文件再 `--data-binary "@file"`，不要直接内联引号（会被 Windows 参数解析吃掉）。

### P0-2 · 真实视频端到端复测（需要你/老师配合）

**现状**：ASR 改造只做了离线 whisper 命令验证和 85 条单测，
**教师端点一次完整视频评分还没跑过**。

**要做**：

1. 重启后端；
2. 用一段**真实答辩录像**（≥3 分钟、正常音量、有清晰人声）触发视频评分；
3. 检查日志：
   - `视频转写使用模型: ...ggml-large-v3-turbo-q5_0.bin`
   - `ASR 语音质量 - 有效语音: ...`
   - `ASR 纠错词表生效`（有替换时）
   - 评分完成后 `video_words` / `video_analysis` 是否落库；
4. 检查学生端/教师端成绩单渲染；
5. 记录：转写文本可读性、有效语音比例、总分、耗时。

**验收**：转写不再混入鼠标声；「文字答辩」「部署」「系统评分」等词基本正确；
低置信片段不被当成“说错”扣分；成绩单能正常展示。

### P1-1 · 视频数值分与导出/排序

**现状**：视频评分只写 `video_analysis` 文本，没有数值列，
教师端不能按视频分排序/统计/导出。

**要做**：新增 `defense_records.video_score DECIMAL(5,2)`（可选 `video_engine VARCHAR(32)`）；
`updateVideoAnalysis` 同步写入；列表/导出/统计读取。
DDL 三处同步：`docs/schema.sql` + 新 `docs/ddl_*.sql` + `diagnose.ps1`。
注意 `analysis_source` 是报告/视频共用单列，后写会覆盖；徽标判断应改用
`video_analysis IS NOT NULL` / `report_doc_score IS NOT NULL`，不要依赖 `analysis_source`。

### P1-2 · 教师端查看转写全文（可核对）

**现状**：`video_words` 只在库里，教师端看不到；AI 说“未提到风险”，教师无法核对。

**要做**：教师端「答辩详情」增加默认收起的「查看视频转写」；
接口 `GET /teacher/defense/video/words/{defenseId}`（类级 `@RequireRole(TEACHER)`）；
返回 `video_words` + 可选分段/置信度 + 有效语音比例。
若要做时间戳/低置信高亮，需要把 `-ojf` 的 segments/confidence 落库
（建议新列 `video_asr_meta` MEDIUMTEXT，存 JSON），不要只存纯文本。

### P1-3 · 工程收口

已知缺口（`VideoAnalysisServiceImpl`）：

- 没有视频僵态清理（报告链路有 `cleanupStaleTasks`，可照抄）；
- `docAnalysisExecutor.execute` 队列满会抛 `RejectedExecutionException`，当前未捕获，锁要等 TTL 才释放；
- 状态 TTL 与锁 TTL 共用 `lockTtlSeconds`，Redis 过期后不会复用已落库结果；
- 幂等指纹只存 Redis，过期后会重新转写；建议落库（新列或 `video_words` 旁存指纹）；
- `analysis_source` 报告/视频互相覆盖（见 P1-1）。

### P1-4 · 「表达」维客观指标

**现状**：表达维仍靠文本猜“是否连贯”，没有语速/停顿/口头语。

**要做**：从 `-ojf` 分段与时间戳计算：
- 语速（有效字数/有效语音秒）；
- 停顿率、>2s 长停顿次数；
- 口头语率（嗯/啊/呃/然后/就是/那个）；
- 重复/改口次数。

作为**证据**喂给点评 prompt，不直接自动扣分；录音质量不合格（音量过低/有效语音不足）时不使用这些指标。
注意：不要因为远场收音差就判“表达差”。

### P2 · 后续可选

- 纠错词表按课题术语扩充（外置文件，不改代码）；
- 可选 ASR 引擎 SenseVoice / Paraformer（中文领域词更好，但引入新组件）；
- GLM-4.6V 只看屏幕/PPT（用户有 6M tokens 推理包）——**当前内容评分不需要**；
- 本地视频大模型：6GB 显存不可行，**不做**。

## 4. 红线与注意事项

1. **API key 只放本地 `src/main/resources/application.yml`**（已 gitignore）或环境变量；
   **绝不提交、绝不打印、绝不贴文档**。本次 key 曾在聊天中出现，建议在智谱控制台重置一次。
2. **只把转写文本 + 声学指标发给云端**，不发视频/音频；这是隐私底线。
3. **不要换本地大模型**：硬件红线仍是 `qwen2.5:3b-16k`；云端文本模型只是评分增强。
4. **不要改 AI 协议标签**：`点评:` / `评分:` / `下一题:` / `总结:` 走 `AiProtocolConstants`。
5. **不要盲目调评分阈值**：N63/N65 的教训是“调阈值会误杀”；先有真实样本再校准。
6. 低功耗机不要放大异步线程池；视频/报告共用 `docAnalysisExecutor`（core=1）是有意串行。
7. 云端额度：GLM-4.7 5M tokens、GLM-4.5-air 12M、GLM-4.6v 6M，均 **2026-12-04 到期**；
   DeepSeek 按量计费，一场约 1~2 分钱。
8. 当前 `application.yml` 的 `app.upload.report.allowed-exts` 仍写多种格式，
   代码白名单实际只收 docx；这是历史配置残留，不影响视频链路。

**GLM 最小调用（不要把 key 写进命令历史）**：

```powershell
# 从本地 application.yml 读 key（不要 echo）
$line = (Select-String -Path 'src/main/resources/application.yml' -Pattern 'api-key:\s*"([^"]+)"' | Select-Object -First 1).Line
$key = [regex]::Match($line, 'api-key:\s*"([^"]+)"').Groups[1].Value
# body 写文件，避免 PowerShell 参数解析吃掉 JSON 引号
$body = '{"model":"glm-4.7","messages":[{"role":"user","content":"Reply with exactly: OK"}],"temperature":0,"max_tokens":50,"stream":false,"thinking":{"type":"disabled"}}'
$tmp = Join-Path $env:TEMP 'glm-body.json'
[IO.File]::WriteAllText($tmp, $body, (New-Object System.Text.UTF8Encoding($false)))
curl.exe -sS --max-time 90 -X POST 'https://open.bigmodel.cn/api/paas/v4/chat/completions' -H "Authorization: Bearer $key" -H 'Content-Type: application/json' --data-binary "@$tmp"
Remove-Item $tmp -Force
```

期望返回：`choices[0].message.content = "OK"`，`usage.completion_tokens_details.reasoning_tokens = 0`。
