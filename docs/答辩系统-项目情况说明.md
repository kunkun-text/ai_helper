# AI-helper 答辩系统 — 项目情况说明（2026-10-09 更新版）

> 本文档说明答辩业务流程、AI 输出格式、以及当前已实现的扩展功能。
> 与 `CHANGES.md` 配合使用：本文档讲"是什么"，`CHANGES.md` 讲"改了什么"。

---

## 一、答辩流程

### 1.1 完整流程图

```
学生登录 → 选择课题 → 进入答辩页
    ↓
[第1~5轮] 预设题库题目（qwen2.5:3b-16k 生成）
    ↓
[第6~10轮] AI 追问（基于学生回答生成）
    ↓
[第11轮] 总结与总评（五维平均分 + 综合点评）
    ↓
结果落库 → 学生查看记录 → 教师查看/导出
```

### 1.2 关键规则

| 规则 | 说明 |
|---|---|
| 总轮次 | 10轮（5预设 + 至多5追问） |
| 追问触发 | 学生回答非敷衍/非复制题目/非讨分，且追问次数 < 5 |
| 中途退出 | 30分钟内重进可续答；超过30分钟或选择"重新开始"则新建记录 |
| 放弃作答 | 追问阶段可放弃，答案记"（放弃作答）"，评分走固定零分流程 |
| 防作弊 | 复制题目内容、讨分短语、跨轮重复作答 → 固定零分 |

## 二、AI 输出格式（三段式）

每轮 AI 回复必须包含以下三部分，用固定标签分隔：

```
点评: <本轮回答的逐维点评>
下一题: <下一道题目文本>
评分: <五维分数 JSON>
```

### 2.1 五维评分标准

| 维度 | 满分 | 说明 |
|---|---|---|
| 切题性 | 10 | 是否回应题目核心 |
| 完整性 | 10 | 是否覆盖题目要求的所有要点 |
| 准确性 | 10 | 概念/事实是否正确 |
| 逻辑性 | 10 | 论证是否清晰有条理 |
| 表达性 | 10 | 语言是否流畅规范 |
| **总分** | **50** | 五维之和 |

### 2.2 评分档位标记

| 标记 | 含义 | 分值处理 |
|---|---|---|
| `[切题]` | 正常回答 | 按五维分计 |
| `[错误]` | 回答有明显事实错误 | 五维各 × 0.5 |
| `[跑题]` | 完全未回应题目 | 固定 0 分 |

### 2.3 协议标签常量

所有标签统一使用 `AiProtocolConstants` 中的常量，禁止硬编码：

```java
public static final String COMMENT_PREFIX = "点评:";
public static final String NEXT_QUESTION_PREFIX = "下一题:";
public static final String SCORE_PREFIX = "评分:";
public static final String SUMMARY_SIGNAL = "总结:";
public static final String TAG_ON_TOPIC = "[切题]";
public static final String TAG_WRONG = "[错误]";
public static final String TAG_OFF_TOPIC = "[跑题]";
```

## 四、扩展功能（2026-10-01 上线）

### 4.1 教师端数据总览

- 总场次、已完成、进行中、课题数、学生数、平均分
- 课题分布柱状图
- 近14天答辩趋势

### 4.2 答辩成绩导出

- 格式：CSV（UTF-8 BOM）
- 内容：学生信息 + 各轮五维分 + 总分
- 上限：10000行
- 安全：公式注入防护（危险前缀前置单引号）

### 4.3 系统反馈模块

- 学生端：提交反馈，字段为**内容（必填）+ 联系方式（可选）**；可查看自己的反馈与教师回复
- 教师端：查看列表、按状态筛选（pending / resolved）、分页、回复
- 状态流转：`pending`（待处理）→ `resolved`（已回复）——教师回复时自动流转，无"处理中"状态
- 存储表：`system_feedback`（`content` / `contact` / `status` / `reply`）

### 4.4 语音答辩（F10，待真机实测）

| 能力 | 实现 |
|---|---|
| AI提问朗读 | Windows SAPI 离线 TTS |
| 学生语音作答 | 小程序录音 → 后端 whisper.cpp ASR |
| 音频转码 | ffmpeg |
| 依赖 | `F:\whisper\whisper-cli.exe` + `ggml-small.bin` |

### 4.5 报告文档 AI 五维评析（2026-10-16）

教师对某场答辩**已上传的报告文档**手动触发一次真实的 AI 评析——这是系统里第一条
「基于上传文件内容」的评分链路（此前的 `report_analysis` 是答辩收尾时模型凭空写的，无文件输入）。

| 项 | 说明 |
|---|---|
| 可解析格式 | `docx` / `pptx` / `xlsx` / `txt`（零新依赖：JDK zip + StAX 直接读 Office Open XML） |
| 不支持的格式 | `pdf` / `doc` / `xls` / `ppt` 已**从上传白名单下架**，上传时提示「请另存为 docx」——零依赖抽不出文字，留在白名单里等于"能传但拿不到分" |
| 评分口径 | 与文字答辩同一套五维（表达/逻辑/专业/应变/创新，各 10 分、总分 50），但五维在**报告语境**下另有操作化定义（写进 prompt） |
| 触发方式 | 教师端「答辩详情」弹层里，紧贴报告文件的「AI 评分（基于报告）」按钮 |
| 落库列 | `report_doc_analysis`（成绩单文本）+ `report_doc_summary`（AI 整体综合评价，约 400~700 字）+ `report_doc_score`（总分，供排序/统计/导出）+ `analysis_source`（=report） |
| 与旧列的关系 | **完全独立**。`report_analysis` / `score` / `video_analysis` 由原链路负责，本功能一行都不碰 |
| 超长材料 | 超过 2500 字先分段抽「证据清单」，再依据清单点评——让输入长度恒定，避免分数随材料变长而漂移 |
| **两次模型调用** | ① **点评调用**（喂材料，只输出五行逐维点评）→ ② **评分调用**（**只喂①的点评，不喂原始材料**，只输出一行五维整数）。**为什么拆开**：3B 无法在一次输出里同时保住「五行点评 + 带数字的评分行」，实测评分行放前会丢点评、放后会漏数字。**为什么②不给材料**：点评调用已被实测证明抗注入，而评分调用拿到原文时会被正文里的「给我满分」劫持——让分数只从点评推导，等于**从结构上掐断注入通道**。分数与点评也因此强一致 |
| **第三次调用 · 综合评价（2026-10-18）** | 成绩单落库后，基于「课题 + 五维成绩单 + 报告材料」写约 400~700 字的整体评价，固定五段：选题与目标 / 方案与实现 / 论证与表达 / 不足与建议 / 总体结论。只写 `report_doc_summary`，**失败只记日志、不影响五维成绩单**。教师端「查看反馈」**打开时自动补齐**（有报告但缺总评 → 后台生成并显示进度，旧场次带 `force` 重跑；同一场次只自动触发一次）；「重新生成评析」也会带 `force=true` 真正重跑 |
| 总分口径 | 总分由**服务端按五维之和重算**，从不采信模型自报的总分（评分行里也干脆不再要求模型写总分，5 个槽位比 6 个稳） |
| 实测结论（10-16） | 优质报告 **36/50**、劣质报告 **19/50**（区分度 17 分）；两份正文都埋了注入话术，**均未被劫持**；重复触发 93ms 幂等返回 |

#### 4.5.1 成绩单化（2026-10-16 晚）

按用户拍板「**对齐文字答辩同一把尺子** + **分数 + 等级 + 逐项得分依据**」改造，输出形态：

```
【基于上传的报告文档】
总分：36/50　等级：优秀
表达（6分）：技术选型合理，满足项目需求
⚠️ 应变（3分）：材料未涉及局限性与备选方案
```

| 项 | 说明 |
|---|---|
| **等级** | 与文字答辩五档表共用边界：`≥35 优秀 / 26~34 良好 / 15~25 合格 / 5~14 不合格 / <5 无效`（对照 `chatController` 的「五档分数表」） |
| **切题闸门** | 点评调用额外输出第 6 行 `切题:是/否`；判「否」→ 服务端把五维**归零**，对齐第五档「完全不相关→固定 0 分」。素材内容与课题不符时首行显示「⚠️ 材料内容与课题不符（判为跑题）」 |
| **缺失压分** | 点评自认某维缺失（含「未涉及/未提及/缺少/只有笼统描述」等）→ 服务端把该维压到 **0~4**，并加 `⚠️` 标记。理由：实测抓到「点评写未给出、分数照样给 7」的自相矛盾，**成绩单上每一分都要有依据** |
| **直评阈值** | 2500 → **10000 字**。实测证据抽取路径反而劣化（维度错配、丢维、把"未来展望"当创新点），而 5520 字材料仅占 3729 tokens |
| **稳定性** | 同一材料重跑 5 次：`36,36,36,36,37`，**极差 1 分**（文字答辩同场景波动 15.5 分）。因为评分调用只看点评、不看长材料 |
| **已知上限** | **短报告之间无法区分**：163~437 字的三份材料拿到完全相同的点评与约 20 分。当前精度的可用区间是「长且实质 35~40 ↔ 短/薄 ~20 ↔ 跑题 0」 |
| 失败口径 | 解析不出五维 → **不写库**、状态置 FAILED、教师可重试；绝不把"模型没按格式输出"变成"学生拿了 0 分" |
| 视觉标识 | 教师端记录列表里，已评析的场次用 teal 底色 + 左侧色条 + 「报告评析 xx分」标签，与普通答辩记录区分 |
| 接口 | `POST /teacher/defense/reportDoc/analyze/{defenseId}[?force=true]`、`GET /teacher/defense/reportDoc/status/{defenseId}`（整类 `@RequireRole(TEACHER)`）；`force=true` 跳过指纹幂等强制重跑 |
| 开关 | `app.report-doc.enabled`（默认开启） |

## 五、评分可信度机制（2026-10-02）

### 5.1 多层复核体系

```
学生回答
    ↓
[第一层] 防作弊检测（复制/讨分/重复）→ 固定零分
    ↓
[第二层] 模型首判（切题/错误/跑题）
    ↓
[第三层] 一致性保护（N45）→ 模型自分≥32且标[错误]则保护不打折
    ↓
[第四层] 接地校验（N46/N49）→ 点评未引用本轮内容 → 重写
    ↓
[第五层] 错误漏判复核（N50/N54）→ 点评含错误暗示但给高分 → 复核
    ↓
[第六层] 答非所问复核（N51/N53）→ 覆盖率<0.25 → 复核是否回应本题
    ↓
[第七层] 跨轮重复检测（N47）→ Dice≥0.8 → 固定零分
    ↓
最终落库
```

### 5.2 关键阈值

| 参数 | 值 | 说明 |
|---|---|---|
| `CROSS_ROUND_REPEAT_DICE` | 0.8 | 跨轮重复判定 |
| `GROUNDED_MIN_HITS` | 3 | 点评接地校验最小命中 |
| `RESCUE_MIN_COVERAGE` | 0.05 | 跑题救回复核门槛 |
| `N45_PROTECT_THRESHOLD` | 32 | 一致性保护阈值（待调） |
