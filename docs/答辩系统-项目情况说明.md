# AI 答辩辅助系统 — 项目情况说明

> 文档目的：梳理项目当前整体情况、答辩核心流程、本次改造内容与验证结果。
> 适用对象：项目维护人员（含新手）。

---

## 一、项目概述

一个「模拟一对一答辩」的辅助系统。AI 作为考官，按预设题库对学生逐题提问，学生口头打字回答，AI 打分、点评并提问下一题，最终给出总体总结。

| 端 | 技术 | 说明 |
|---|---|---|
| 后端 | Spring Boot 3.5 + Spring AI 1.1.2 | 负责出题、调模型、评分持久化、会话记忆 |
| 本地大模型 | Ollama + qwen2.5:3b-16k | 非思考型模型，速度快；上下文 16384 |
| 数据库 | MySQL（库 `ai_helper`）+ Redis | MySQL 存题库/评分/记录，Redis 存会话记忆 |
| 前端 | 微信小程序（原生 + Taro 风格页） | 答辩交互页 |

---

## 二、答辩核心流程（当前已落地的闭环）

```
① 后端从题库直接出「第1题」（不调模型，零延迟、不泄露答案要点）
② 学生在页面输入回答 → 调 /api/chat
③ AI 依据「标准答案要点」打分 + 点评 + 提问下一题
④ 每轮评分异步持久化到 defense_score_record 表
⑤ 预设题用完后，允许 AI 追加追问（当前上限 2 个）
⑥ 最后一轮结束后 AI 输出总结 → 前端结束答辩弹窗
```

### AI 每轮输出的三段式格式（严格固定）

```
点评:（40字以内，先肯定优点，再指出不足和一条建议）
评分:总分/50|表达分|逻辑分|专业分|应变分|创新分（五维相加=总分）
下一题:（30字以内）
```

最后一轮不出「下一题」，改为：
```
总结:（100字以内，整场总体评价）
```

### 打分客观性规则（已写入 prompt + 后端兜底）

- 只有回答正确、完整、条理清晰才给高分。
- 回答错误、答非所问、含糊其辞、直接说「不知道」→ 对应维度只给 0-4 分，总分不超过 25/50。
- 后端强制校验：各维度 0-10 分、展示总分一律 = 五维之和，杜绝「不知道还打 40 分」。

## 三、本次改造内容（相对旧版，解决的核心问题）

旧版问题：格式乱、分数不客观、标签漏出、评价重复显示、每轮都弹「答辩完成」。

### 后端（chatController.java）

1. **重写三段式 prompt**：点评在前 → 评分 → 下一题；加入打分客观规则。
2. **首轮由后端直接出题**，不再调模型（之前会漏答案要点/首轮误出评分）。
3. **历史摘要提取适配新格式**：从「点评:」提取，不再把完整的评分行塞回下一轮 prompt。
4. **评分解析强制一致性**（ScorePersistenceServiceImpl）：维度限 0-10、总分=五维求和。
5. **硬性兜底防死循环**：追问数达到上限后不再出下一题，强制总结。
6. **maxTokens 调整**：256 → 320，避免三段式被截断。
7. **legacyScore 优先取后端校验后的 totalScore**，保证落库分数与页面一致。

### 前端（defense.js）

1. **解析入口兼容全角冒号**（点评:/评分:/下一题: 全角半角都认）。
2. **重写 parseSegmentFormat**：
   - 气泡只显示「点评」自然语言文本（不再重复显示评分）。
   - 评分/下一题走下方结构化区块，排版清晰。
   - 展示总分 = 五维求和。
   - 支持「总结:」行解析。
3. **修复误触发生成完成**：只有出「总结」才结束答辩，普通轮打分不再弹窗。

## 五、实测验证结果（topicId=28）

- 首轮：`你好，我是本次答辩的AI考官。现在我们开始第1题：请说明Hadoop生态系统的核心组件及其在本课题中的作用。`
  → ✅ 后端直接出题、无评分格式、无答案泄露
- 学生回答后 AI 返回：
  ```
  点评:回答基本正确，但缺少具体在本课题中的详细作用描述，建议补充说明HDFS在数据存储方面的具体优势以及如何提升数据处理效率。
  评分:35/50|8|7|7|7|6
  下一题:请进一步解释MapReduce是如何实现大规模数据处理的？
  ```
  → ✅ 点评在前、五维 8+7+7+7+6=35、下一题短、无泄露

## 七、运维要点（新手必看）

1. **启动顺序**：MySQL → Redis → Ollama（`ollama serve`）→ 后端（`mvn spring-boot:run`，端口 8080）。
2. **模型**：必须用 `qwen2.5:3b-16k`（Ollama 已建）。不要换回 `qwen3` 思考型模型（会因思考 token 消耗导致空回复/超时）。
3. **清理端口**：`Get-NetTCPConnection -LocalPort 8080 -State Listen` 查占用 PID，`Stop-Process -Id <PID> -Force`。
4. **重开会话**：每次进入答辩页前端会自动调 `/api/chat/clear` 清空 Redis 旧会话。
5. **改代码后**：重新 `mvn spring-boot:run`，前端页面受静态资源影响需重新编译小程序。
