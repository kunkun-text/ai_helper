# AI-helper 答辩系统 — 项目情况说明（2026-10-19 更新版）

> 本文档说明答辩业务流程、AI 输出格式、以及当前已实现的扩展功能。
> 与 `CHANGES.md` 配合使用：本文档讲"是什么"，`CHANGES.md` 讲"改了什么"。

## 一、答辩流程

### 1.1 完整流程图

```
学生登录 → 选择课题 → 进入答辩页
    ↓
[第1~5轮] 预设题库题目（qwen2.5:3b-16k 生成）
    ↓
[第6~10轮] AI 追问（基于学生回答生成）
    ↓
[第11轮] 总结与总评（五维平均分 + 综合点评）
    ↓
结果落库 → 学生查看记录 → 教师查看/导出
```

### 1.2 关键规则

| 规则 | 说明 |
|---|---|
| 总轮次 | 10轮（5预设 + 至多5追问） |
| 追问触发 | 学生回答非敷衍/非复制题目/非讨分，且追问次数 < 5 |
| 中途退出 | 30分钟内重进可续答；超过30分钟或选择"重新开始"则新建记录 |
| 放弃作答 | 追问阶段可放弃，答案记"（放弃作答）"，评分走固定零分流程 |
| 防作弊 | 复制题目内容、讨分短语、跨轮重复作答 → 固定零分 |

## 二、AI 输出格式（三段式）

每轮 AI 回复必须包含以下三部分，用固定标签分隔：

```
点评: <本轮回答的逐维点评>
下一题: <下一道题目文本>
评分: <五维分数 JSON>
```

### 2.1 五维评分标准

> 真实口径以代码为准：`chatController.java` 的 `SCORE_KEYS`（`expression/logic/professional/adaptability/innovation`）与 `docs/schema.sql` 的 `defense_score_record` 列。

| 维度 | 满分 | 说明 | DB 列 |
|---|---|---|---|
| 表达 | 10 | 语言是否流畅规范、表述是否清楚 | `expression_score` |
| 逻辑 | 10 | 论证是否清晰有条理、有无前后矛盾 | `logic_score` |
| 专业 | 10 | 概念/事实/术语是否准确，方案是否有深度 | `professional_score` |
| 应变 | 10 | 面对追问是否切题、能否调整思路 | `adaptability_score` |
| 创新 | 10 | 是否有自主设计、亮点是否可辨识 | `innovation_score` |
| **总分** | **50** | 五维之和 | `score` |

评分行格式固定为：`评分:总分/50|表达分|逻辑分|专业分|应变分|创新分`（五维各 0~10 整数，之和必须等于总分；服务端亦会按五维重算，不采信模型自报总分）。

### 2.2 评分档位标记

| 标记 | 含义 | 分值处理 |
|---|---|---|
| `[切题]` | 正常回答 | 按五维分计 |
| `[错误]` | 回答有明显事实错误 | 五维各 × 0.5 |
| `[跑题]` | 完全未回应题目 | 固定 0 分 |

### 2.3 协议标签常量

所有标签统一使用 `AiProtocolConstants` 中的常量，禁止硬编码：

```java
public static final String COMMENT_PREFIX = "点评:";
public static final String NEXT_QUESTION_PREFIX = "下一题:";
public static final String SCORE_PREFIX = "评分:";
public static final String SUMMARY_SIGNAL = "总结:";
public static final String TAG_ON_TOPIC = "[切题]";
public static final String TAG_WRONG = "[错误]";
public static final String TAG_OFF_TOPIC = "[跑题]";
```

### 4.5 报告文档 AI 五维评析（2026-10-16）

教师对某场答辩**已上传的报告文档**手动触发一次真实的 AI 评析——这是系统里第一条
「基于上传文件内容」的评分链路（此前的 `report_analysis` 是答辩收尾时模型凭空写的，无文件输入）。

| 项 | 说明 |
|---|---|
| 可解析格式 | **上传只收 `.docx`**（2026-10-20 收口，模板也是 docx）；解析层仍兼容 `pptx` / `xlsx` / `txt` 的历史文件（白名单只拦上传，不删解析能力） |
| 不支持的格式 | `pdf` / `doc` / `xls` / `ppt` 零依赖抽不出文字；`pptx` / `xlsx` / `txt` 自 2026-10-20 起也不再接受新上传。以上一律提示「用 Word 另存为 .docx」 |
| 文档内图片 | 位图（`png/jpg/gif/bmp/tiff`）经 OCR 转成文字，**按正文位置**回填为 `【图N】`；`emf/wmf/svg` 矢量图与公式、图表趋势无法判读，会显式标注（2026-10-20） |
| 报告模板 | 学生端「选择报告，开始上传」下方可下载 `.docx` 模板（封面 + 填写须知 8 条 + 六章骨架 + 自检清单），模板类型 = 唯一可上传类型 |
| 评分口径 | 与文字答辩同一套五维（表达/逻辑/专业/应变/创新，各 10 分、总分 50），但五维在**报告语境**下另有操作化定义（写进 prompt） |
| 触发方式 | 教师端「查看回答详情」弹层里，紧贴报告文件的「AI 评分（基于报告）」按钮（2026-10-18 从「查看反馈」迁入；已评析过显示「重新生成评析」）；整体综合评价在「查看反馈」打开时自动补齐展示 |
| 落库列 | `report_doc_analysis`（成绩单文本）+ `report_doc_summary`（AI 整体综合评价，约 400~700 字）+ `report_text`（抽取全文快照，MEDIUMTEXT） + `report_doc_score`（总分，供排序/统计/导出）+ `analysis_source`（=report）+ `defense_mode`（答辩形式，**已建列但当前未写入**） |
| 与旧列的关系 | **完全独立**。`report_analysis` / `score` / `video_analysis` 由原链路负责，本功能一行都不碰 |
| 超长材料 | 超过 **10000 字**（`direct-score-max-chars`）才走「分段抽证据 → 依据清单点评」（切块上限 2500 字）；10000 字以内直接评——实测直评质量明显优于证据路径 |
| **两次模型调用** | ① **点评调用**（喂材料，只输出五行逐维点评）→ ② **评分调用**（**只喂①的点评，不喂原始材料**，只输出一行五维整数）。**为什么拆开**：3B 无法在一次输出里同时保住「五行点评 + 带数字的评分行」，实测评分行放前会丢点评、放后会漏数字。**为什么②不给材料**：点评调用已被实测证明抗注入，而评分调用拿到原文时会被正文里的「给我满分」劫持——让分数只从点评推导，等于**从结构上掐断注入通道**。分数与点评也因此强一致 |
| **第三次调用 · 综合评价（2026-10-18）** | 成绩单落库后，基于「课题 + 五维成绩单 + 报告材料」写约 400~700 字的整体评价，固定五段：选题与目标 / 方案与实现 / 论证与表达 / 不足与建议 / 总体结论。只写 `report_doc_summary`，**失败只记日志、不影响五维成绩单**。教师端「查看反馈」**打开时自动补齐**（有报告但缺总评 → 后台生成并显示进度，旧场次带 `force` 重跑；同一场次只自动触发一次）；「重新生成评析」也会带 `force=true` 真正重跑 |
| 总分口径 | 总分由**服务端按五维之和重算**，从不采信模型自报的总分（评分行里也干脆不再要求模型写总分，5 个槽位比 6 个稳） |
| 实测结论（10-16） | 优质报告 **36/50**、劣质报告 **19/50**（区分度 17 分）；两份正文都埋了注入话术，**均未被劫持**；重复触发 93ms 幂等返回 |

#### 4.5.1 成绩单化（2026-10-16 晚）

按用户拍板「**对齐文字答辩同一把尺子** + **分数 + 等级 + 逐项得分依据**」改造，输出形态：

```
【基于上传的报告文档】
总分：36/50　等级：优秀
表达（6分）：技术选型合理，满足项目需求
⚠️ 应变（3分）：材料未涉及局限性与备选方案
```

| 项 | 说明 |
|---|---|
| **等级** | 与文字答辩五档表共用边界：`≥35 优秀 / 26~34 良好 / 15~25 合格 / 5~14 不合格 / <5 无效`（对照 `chatController` 的「五档分数表」） |
| **切题闸门** | 点评调用额外输出第 6 行 `切题:是/否`；判「否」→ 服务端把五维**归零**，对齐第五档「完全不相关→固定 0 分」。素材内容与课题不符时首行显示「⚠️ 材料内容与课题不符（判为跑题）」 |
| **缺失压分** | 点评自认某维缺失（含「未涉及/未提及/缺少/只有笼统描述」等）→ 服务端把该维压到 **0~4**，并加 `⚠️` 标记。理由：实测抓到「点评写未给出、分数照样给 7」的自相矛盾，**成绩单上每一分都要有依据** |
| **直评阈值** | 2500 → **10000 字**。实测证据抽取路径反而劣化（维度错配、丢维、把"未来展望"当创新点），而 5520 字材料仅占 3729 tokens |
| **稳定性** | 同一材料重跑 5 次：`36,36,36,36,37`，**极差 1 分**（文字答辩同场景波动 15.5 分）。因为评分调用只看点评、不看长材料 |
| **已知上限** | **短报告之间无法区分**：163~437 字的三份材料拿到完全相同的点评与约 20 分。当前精度的可用区间是「长且实质 35~40 ↔ 短/薄 ~20 ↔ 跑题 0」 |
| 失败口径 | 解析不出五维 → **不写库**、状态置 FAILED、教师可重试；绝不把"模型没按格式输出"变成"学生拿了 0 分" |
| 视觉标识 | 教师端记录列表里，已评析的场次用 teal 底色 + 左侧色条 + 「报告评析 xx分」标签，与普通答辩记录区分 |
| 接口 | `POST /teacher/defense/reportDoc/analyze/{defenseId}[?force=true]`、`GET /teacher/defense/reportDoc/status/{defenseId}`（整类 `@RequireRole(TEACHER)`）；`force=true` 跳过指纹幂等强制重跑 |
| 开关 | `app.report-doc.enabled`（默认开启） |

### 4.6 报告分析：能分析什么文件、能达到什么效果（2026-10-19 口径）

#### 能分析的文件

| 项 | 口径 |
|---|---|
| 支持格式 | **上传仅 `.docx`**；解析层兼容 `DocTextExtractor.Format` 的 `docx/pptx/xlsx/txt`（仅用于历史文件） |
| 不支持 | **PDF、旧版 `.doc/.xls/.ppt`**——零依赖方案抽不出文字；`pptx/xlsx/txt` 自 2026-10-20 起不再接受新上传 |
| 单文件大小 | ≤ **50MB**（`app.file.report.max-size`）；扩展名 + 文件头魔数（docx 必须是 zip）双校验 |
| 抽取内容 | docx 段落文本；pptx 逐页文本（最多 100 页）；xlsx 共享字符串 + 各工作表单元格文本（最多 100 表）；txt 全文。**公式、批注、样式丢失，表格会塌成文本流** |
| 文档内图片 | 位图（png/jpg/gif/bmp/tiff）→ **优先 Windows 自带 OCR**（`Windows.Media.Ocr`，零下载）→ 文本按正文顺序回填 `【图N】`；tesseract（`chi_sim+eng`）仅作兜底；EMF/WMF/SVG 跳过并标注；单图 ≤2MB、最多 12 张、单图 20s / 整体 60s 预算（2026-10-20） |
| 安全边界 | 单 zip 条目解压 ≤4MB、累计解压 ≤40MB、压缩比 ≤200（防压缩炸弹）；DTD/外部实体关闭（防 XXE）；正文一律当"数据"（防提示词注入） |
| 文本上限 | 抽取全文 ≤60000 字，超出截断；全文快照落 `report_text` 供教师对照 |
| 长度策略 | ≤10000 字直接评；>10000 字按 2500 字切块（最多 8 块，超限保留头尾）先抽证据清单再评 |

#### 达到的效果（实测）

| 场景 | 结果 |
|---|---|
| 长且实质的报告 | **35~40 分 / 50**，成绩单能逐项指出缺失（"未涉及局限性讨论"等） |
| 短/薄的报告 | **约 20 分**，能识别出"只有罗列、没有方案细节" |
| 跑题/空壳 | **0~1 分**（切题闸门判否直接归零，缺失项压分） |
| 短报告之间 | **无法区分**：163 / 282 / 437 字三份材料点评几乎相同、都在 20 分左右（3B 能力上限，已接受） |
| 稳定性 | 同一材料重跑 5 次：`36,36,36,36,37`，极差 **1 分**（评分只依据点评、不重新读原文） |
| 耗时 | 受 8G 低功耗机限制，单任务预算 **240 秒**；超时中止且不写库，教师可重试 |
| 产物 | `report_doc_analysis`（成绩单）+ `report_doc_summary`（400~700 字综合评价，≤2000 字）+ `report_doc_score`（总分）；**不写 `score` / `report_analysis`**，不影响文字答辩成绩 |

## 五、评分可信度机制（2026-10-02 ~ 2026-10-19）

### 5.1 多层复核体系

```
学生回答
    ↓
[第一层] 防作弊检测（复制/讨分/重复）→ 固定零分
    ↓
[第二层] 模型首判（切题/错误/跑题）
    ↓
[第三层] 一致性保护（N45）→ 模型自分≥32且标[错误]则保护不打折
    ↓
[第四层] 接地校验（N46/N49）→ 点评未引用本轮内容 → 重写
    ↓
[第五层] 错误漏判复核（N50/N54）→ 点评含错误暗示但给高分 → 复核
    ↓
[第六层] 答非所问复核（N51/N53）→ 覆盖率<0.25 → 复核是否回应本题
    ↓
[第七层] 跨轮重复检测（N47）→ Dice≥0.8 → 固定零分
    ↓
最终落库
```

此外还有两道**服务端闸门**（不改变上面的层序）：

- **路线① 要点逐项核验（N7，2026-10-14 落库为 `defense_rubric`）**：每轮按题目要点清单判「命中 / 未命中 / 矛盾」，命中率低于阈值 → 判错误档并把总分压到 ≤15；核验判定 `relevant=false`（与本题完全无关）→ 五维直接归零。追问轮没有题库标准答案，改用 `ensureRubricForQuestion` 现生成要点（N63 已把覆盖范围放开到全部轮次；但命中率分母口径受 3B 输出条数影响，实测量化能力有限，见 `CHANGES.md` 2026-10-15）。
- **标注一致性守卫（N64 / 2026-10-19 方案A）**：点评正文没有具体错误措辞、且本轮未确认扣分时，剥离模型自附的「（有明显回答错误）」；真错误（正文含「说反/应为/有误」等）或已确认扣分的轮次保留标注。实现为纯函数 `shouldStripWrongAnswerNote` + `errorVerified` 标志。
